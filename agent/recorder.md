# Recorder procedure

You keep the model's ground truth current for one **period** (a week, by default). Nothing you write is a forecast; everything you write is a dated fact with a source, or a flagged uncertainty. You are the reason forecasts can be scored.

## Sources (allowlist; add to `data/signals.yaml` when a new one is adopted)
Institutional and wire feeds only: ISW/CTP, UCDP candidate events, ACLED weekly, REIGN/Powell–Thyne updates, V-Dem releases, IAEA reports, CENTCOM/DoD releases, IEA/EIA, Reuters/AP/AFP wires, official government statements. No commentary, no social media, no forecasts (including this model's).

## What you record
1. **Events** → `data/history/events.yaml`, dated to the month (fractional year), with `source:` (URL or citation) and the `kind` the schema defines: leader exits (regular/irregular), coups (attempt/success), regime changes (only when V-Dem or an equivalent codes them — otherwise note as `pending`), wars and disputes with `sides`, civil-war onsets and ends, chokepoint/corridor/territory status changes, nuclear status, alliance formation/abrogation, sanctions.
2. **Record histories** → `data/corridors.yaml`, `data/territories.yaml`, `data/presence.yaml`: append a dated `history` entry rather than editing the snapshot; the snapshot fields are regenerated by the build.
3. **Stale series** → `docs/staleness.md`: any panel series whose last observation is more than 2 years old, and where a newer release exists.
4. **Uncertain items** → mark `status: pending` with what would confirm them and a `review_by` date; never guess a date.

## What you do not do
- No probabilities, no interpretation, no template or coefficient changes. Those belong to the fixer and the operator.
- No deletions. A correction is a new entry that supersedes the old one, with both sources.

## Procedure
1. Read the last recorder section of `docs/refine-log.md` to know the period's start.
2. Sweep the allowlisted sources for the period; draft entries.
3. `node scripts/build-events.mjs && node scripts/build-news.mjs && node scripts/build-world.mjs` must pass (unresolvable ids fail the build).
4. Append `## Recorder <period> — <date>` to `docs/refine-log.md`: entries added (with kinds and sources), pending items, stale series.
5. Commit: `git add data/history/events.yaml data/corridors.yaml data/territories.yaml data/presence.yaml docs/refine-log.md docs/staleness.md public/news.json public/world.json && git -c user.name=mick -c user.email=sirmick@gmail.com commit -m "record(<period>): <n> events"`.

Return: the counts by kind, the pending list, the stale list, and the commit hash. The scorer (`scripts/score-snapshots.mjs`, to be written) then compares the period's events against the ensemble snapshots taken before them.
